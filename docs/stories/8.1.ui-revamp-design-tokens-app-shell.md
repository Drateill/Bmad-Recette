# Story 8.1: UI Revamp - Design Tokens & App Shell

## Status
Approved

## Story
**As a** user,
**I want** a consistent visual system and navigation across the app,
**so that** the UI feels cohesive and easy to use.

## Acceptance Criteria

1. Design tokens for color, typography, spacing, and motion match `docs/front-end-spec.md` (light and dark modes included)
2. Global styles apply the tokenized system consistently across shared UI primitives and page chrome
3. Primary navigation matches the spec: web sidebar with 5 sections; mobile tab bar with 5 sections
4. Responsive breakpoints and layout rules align with the spec (mobile/tablet/desktop/wide)
5. Theme toggle supports Auto/Light/Dark and persists user preference
6. Web app shell updates apply to existing routes without breaking current navigation (`/login`, `/register`, `/recipes`)

## Tasks / Subtasks

- [ ] Task 1: Define design tokens from spec (AC: 1)
  - [ ] Capture color palette (light/dark) as shared tokens
  - [ ] Define typography scale and font families
  - [ ] Define spacing and radius scale
  - [ ] Define motion durations/easings

- [ ] Task 2: Apply tokens to shared UI primitives (AC: 2)
  - [ ] Update base buttons, inputs, cards, and typography styles
  - [ ] Ensure consistent spacing and sizing across layouts

- [ ] Task 3: Update app shell navigation patterns (AC: 3)
  - [ ] Implement web sidebar navigation with 5 sections
  - [ ] Implement mobile tab bar navigation with 5 sections

- [ ] Task 4: Align responsive layout behavior (AC: 4)
  - [ ] Implement breakpoint-based layout changes per spec
  - [ ] Confirm layout behavior across mobile, tablet, desktop, wide

- [ ] Task 5: Add theme toggle and persistence (AC: 5)
  - [ ] Implement Auto/Light/Dark selection
  - [ ] Persist preference and honor system setting

- [ ] Task 6: Wire app shell into existing web routes (AC: 6)
  - [ ] Apply shell to `/recipes` and `/recipes/:id` pages
  - [ ] Ensure public routes retain minimal chrome (login/register)
