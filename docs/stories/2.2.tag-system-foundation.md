6. Tag assignment endpoint supports multiple tags in single operation (bulk insert)
7. Efficient indexing for tag-based queries (covering indexes on RecipeTags)

### Database Schema Details

**TagCategory Model** [Source: architecture/data-models.md#tag, architecture/database-schema.md]
```prisma
model TagCategory {
  id        String   @id @default(uuid())
  name      String
  slug      String   @unique
  sortOrder Int
  createdAt DateTime @default(now())

  tags      Tag[]

  @@map("tag_categories")
}
```

**Tag Model** [Source: architecture/data-models.md#tag, architecture/database-schema.md]
```prisma
model Tag {
  id         String   @id @default(uuid())
  categoryId String
  name       String
  slug       String
  isSystem   Boolean  @default(false)
  userId     String?
  color      String?
  createdAt  DateTime @default(now())

  category   TagCategory @relation(fields: [categoryId], references: [id])
  user       User?       @relation(fields: [userId], references: [id], onDelete: Cascade)
  recipes    RecipeTag[]

  @@unique([categoryId, slug])              // For system tags
  @@unique([categoryId, slug, userId])      // For user tags
  @@index([categoryId])
  @@index([userId])
  @@index([slug])
  @@map("tags")
}
```

**RecipeTag Junction Model** [Source: architecture/data-models.md#tag, architecture/database-schema.md]
```prisma
model RecipeTag {
  id        String   @id @default(uuid())
  recipeId  String
  tagId     String
  createdAt DateTime @default(now())

  recipe    Recipe   @relation(fields: [recipeId], references: [id], onDelete: Cascade)
  tag       Tag      @relation(fields: [tagId], references: [id], onDelete: Cascade)

  @@unique([recipeId, tagId])
  @@index([recipeId])
  @@index([tagId])
  @@index([recipeId, tagId])  // Covering index
  @@map("recipe_tags")
}
```

### Tag System Design Decisions

**1. Dual Unique Constraints for Tags** [Source: architecture/data-models.md#tag, PRD AC 5]
- System tags: @@unique([categoryId, slug]) - prevents duplicate "Vegetarian" tags globally
- User tags: @@unique([categoryId, slug, userId]) - allows different users to create custom tags with same slug
- Prisma limitation: Cannot have conditional unique constraints, so we enforce at application level

**2. isSystem Flag** [Source: PRD FR10]
- isSystem=true: Predefined tags, userId=null, immutable (cannot be deleted)
- isSystem=false: User-created custom tags, userId set, user can delete
- Application logic must prevent modification of system tags

**3. Color Field** [Source: architecture/data-models.md#tag]
- Optional hex color for UI display (#FF5733)
- System tags can have default colors
- User tags default to null (UI uses category color)

**4. Cascade Deletion Strategy**
- Deleting User → CASCADE deletes user's custom tags (isSystem=false)
- Deleting Recipe → CASCADE deletes all RecipeTags (tag assignments)
- Deleting Tag → CASCADE deletes all RecipeTags using that tag
- System tags cannot be deleted (enforced at application level)

### API Endpoint Specifications

**POST /api/recipes/:recipeId/tags** [Source: AC 6, PRD FR9]
- **Purpose**: Bulk assign tags to recipe (replaces existing tags)
- **Authorization**: User must own the recipe
- **Request Body**: `{ tagIds: string[] }`
- **Validation**: All tagIds must be valid UUIDs and exist in database
- **Transaction**: Delete existing RecipeTags + Insert new ones atomically
- **Response**: 200 OK with updated recipe.tags array

**GET /api/tag-categories** [Inferred from tag system requirements]
- **Purpose**: Fetch all tag categories with nested tags
- **Response**: Array of TagCategory with tags[] populated
- **Ordering**: By sortOrder ascending

**GET /api/tags?categoryId=uuid** [Inferred from filtering requirements]
- **Purpose**: Fetch tags filtered by category
- **Query Params**: categoryId (optional), isSystem (optional), userId (optional)
- **Response**: Array of Tag objects

### Indexing Strategy

**Covering Index for Tag Queries** [Source: AC 7, PostgreSQL best practices]
- `@@index([recipeId, tagId])` on RecipeTags table
- Enables efficient queries: "Find all recipes with tag X"
- Supports JOIN operations between recipes and tags
- Prevents table scans on large datasets

**Additional Indexes** [Source: architecture/database-schema.md]
- Tag.categoryId: Filtering tags by category
- Tag.userId: Finding user's custom tags
- Tag.slug: Tag lookup by slug
- RecipeTag.recipeId: Finding tags for a recipe
- RecipeTag.tagId: Finding recipes with a tag

### Performance Considerations

✓ **PASS** - Performance optimizations in place

**Database Indexing:**
- Covering index on `(recipeId, tagId)` enables efficient tag-based recipe queries
- Individual indexes on `categoryId`, `userId`, `slug` for common lookups
- Unique indexes double as query optimization

**Query Optimization:**
- Repository pattern enables easy query optimization in future
- `include` statements properly used for eager loading related data
- Bulk operations use `createMany` with skipDuplicates

**Transaction Management:**
- Tag assignment uses single transaction for delete + insert operations
- Minimizes database round-trips

**Potential Future Optimizations:**
- Consider tag caching for frequently accessed system tags (Redis)
- Add pagination for user tag endpoints if users create many custom tags
