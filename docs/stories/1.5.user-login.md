# Story 1.5: User Login with Email/Password

## Status
Done

## Story
**As a** registered user,
**I want** to log in using my email and password,
**so that** I can access my recipes and personalized data.

## Acceptance Criteria
1. POST /api/auth/login endpoint created accepting {email, password} with validation
2. Email lookup case-insensitive, password verified using bcrypt compare
3. Successful login returns 200 OK with user object and JWT access token (15 min expiry) + refresh token (7 days expiry)
4. Failed login returns 401 Unauthorized without revealing whether email or password was incorrect
5. Refresh token stored in httpOnly cookie (secure, sameSite: strict) for security
6. Rate limiting applied: max 10 login attempts per IP per hour to prevent brute force
7. Failed login attempts logged for security monitoring

### API Specification

**Endpoint:** POST /api/auth/login

**Request Body:**
```typescript
{
  email: string;      // Valid email format (case-insensitive)
  password: string;   // User's password
}
```

**Success Response (200 OK):**
```typescript
{
  user: {
    id: string;
    email: string;
    firstName: string;
    createdAt: string;  // ISO 8601 timestamp
  };
  accessToken: string;   // JWT, expires in 15 minutes
  // refreshToken sent via httpOnly cookie, not in body

```

**Cookie Header (Set-Cookie):**
```
refreshToken=<jwt_token>; HttpOnly; Secure; SameSite=Strict; Path=/api/auth; Max-Age=604800
```

**Error Responses:**
- 400 Bad Request: Invalid email format or missing fields
- 401 Unauthorized: Invalid credentials (generic message for security)
- 429 Too Many Requests: Rate limit exceeded (10 attempts/hour)

### JWT Token Configuration

**Access Token** (same as Story 1.4):
- Expiration: 15 minutes
- Payload: `{ sub: userId, email: string, type: 'access' }`
- Used for: API authentication via Bearer token in Authorization header
- Storage: Frontend memory (never localStorage for security)

**Refresh Token** (same as Story 1.4):
- Expiration: 7 days
- Payload: `{ sub: userId, type: 'refresh' }`
- Stored: Redis with key `refresh_token:${userId}` and TTL 7 days
- Sent to client: httpOnly cookie (XSS-proof)
- Used for: Renewing access token (Story 1.7)

**JWT Secret:**
- Access via ConfigService: `configService.get('jwt.secret')`
- Same secret used for both access and refresh tokens

[Source: docs/architecture/security-and-performance.md#authentication-security]

### Security Requirements

#### 1. Generic Error Messages (Anti-Enumeration)

**Problem:** Specific error messages reveal whether an email exists
- "Email not found" → Attacker knows email doesn't exist
- "Password incorrect" → Attacker knows email exists

**Solution:** Always return generic "Invalid credentials" message
```typescript
// BAD - Reveals information
if (!user) throw new UnauthorizedException('Email not found');
if (!isPasswordValid) throw new UnauthorizedException('Password incorrect');

// GOOD - Generic message
if (!user || !isPasswordValid) {
  throw new UnauthorizedException('Invalid credentials');
}
```

[Source: docs/architecture/security-and-performance.md#backend-security]

#### 2. httpOnly Cookies for Refresh Tokens

**Why httpOnly?**
- Prevents JavaScript access (XSS protection)
- Browser automatically sends with requests to same domain
- More secure than localStorage or sessionStorage

**Cookie Configuration:**
```typescript
res.cookie('refreshToken', token, {
  httpOnly: true,           // No JavaScript access
  secure: nodeEnv === 'production',  // HTTPS only in production
  sameSite: 'strict',       // CSRF protection
  path: '/api/auth',        // Only sent to auth endpoints
  maxAge: 7 * 24 * 60 * 60 * 1000  // 7 days
});
```

**Development vs Production:**
- Development (HTTP): secure: false
- Production (HTTPS): secure: true

[Source: docs/architecture/security-and-performance.md#authentication-security]

#### 3. Rate Limiting

**Login Rate Limits:**
- Limit: 10 requests per IP address per hour
- Stricter than registration (5/hour) to prevent brute force
- Reset: After 1 hour from first request

**Implementation:**
```typescript
@Throttle(10, 3600)
@Post('login')
async login(@Body() dto: LoginDto) { ... }
```

[Source: docs/prd/epic-details.md - Story 1.5 AC 6]

#### 4. Security Logging

**What to Log:**
- Failed login attempts: `{ event: 'login_failed', email, ip, timestamp, reason }`
- Successful logins (optional): `{ event: 'login_success', userId, email, ip, timestamp }`
- Rate limit exceeded: Automatically logged by @nestjs/throttler

**What NOT to Log:**
- Passwords (plaintext or hashed)
- Full JWT tokens
- Sensitive user data

**Log Level:**
- Failed attempts: `logger.warn()` (not error - expected behavior)
- Successful logins: `logger.info()` (if implemented)

### Case-Insensitive Email Lookup

**Why Case-Insensitive?**
- Better UX: Users often forget exact casing of their email
- test@example.com should match TEST@EXAMPLE.COM, Test@Example.com, etc.

**Prisma Implementation:**
```typescript
// In AuthRepository.findByEmail()
async findByEmail(email: string): Promise<User | null> {
  return this.prisma.user.findFirst({
    where: {
      email: {
        equals: email,
        mode: 'insensitive'  // PostgreSQL ILIKE
      }
    }
  });
}
```

**Database Consideration:**
- PostgreSQL uses ILIKE for case-insensitive matching
- Email uniqueness constraint is case-sensitive at DB level
- Email should be stored in lowercase for consistency (optional enhancement)

### Error Handling

**Login-Specific Error Scenarios:**

1. **Invalid Email Format**
   - Trigger: Email fails @IsEmail() validation
   - Response: 400 Bad Request
   - Handled by: ValidationPipe (automatic)

2. **Invalid Credentials**
   - Trigger: User not found OR password incorrect OR OAuth-only user
   - Response: 401 Unauthorized with message "Invalid credentials"
   - Handled by: throw UnauthorizedException('Invalid credentials')

3. **Rate Limit Exceeded**
   - Trigger: More than 10 login attempts in 1 hour
   - Response: 429 Too Many Requests
   - Handled by: @nestjs/throttler (automatic)

**Error Response Format:**
```typescript
// 401 Unauthorized
{
  error: {
    code: "INVALID_CREDENTIALS",
    message: "Invalid credentials",
    timestamp: "2026-01-07T14:30:00.000Z",
    requestId: "uuid-here"
  }
}
```

// apps/api/src/modules/auth/strategies/jwt.strategy.ts
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';
import { ConfigService } from '@nestjs/config';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor(
    private configService: ConfigService,
    private authRepository: AuthRepository
  ) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: configService.get('jwt.secret'),
    });
  }

  async validate(payload: any) {
    // payload = { sub: userId, email, type: 'access' }
    const user = await this.authRepository.findById(payload.sub);
    if (!user) {
      throw new UnauthorizedException();
    }
    return { id: user.id, email: user.email, firstName: user.firstName };
  }
}
