## Story
**As a** user,
**I want** to create recipes from predefined templates,
**so that** I can quickly add common recipe types without starting from scratch.

## Acceptance Criteria

1. GET /api/recipe-templates endpoint returns list of 5-10 predefined templates
2. Templates include: Dessert, Main Course, Appetizer, Beverage, Salad, Soup, Breakfast, Snack
3. Each template has: name, icon, defaultTags (pre-selected tags), defaultFields (e.g., servings: 4), placeholderIngredients, placeholderSteps
4. POST /api/recipes/from-template endpoint accepts templateId and creates recipe pre-filled with template defaults
5. User can immediately edit the template-created recipe (it's a normal recipe, not linked to template)
6. Templates stored as JSON configuration (no database table needed for MVP)
7. Frontend displays templates as visual cards during recipe creation flow

### Template Loading Strategy

**Static Templates File** [Source: AC 6]
```typescript
// apps/api/src/modules/recipes/templates/recipe-templates.ts
export const RECIPE_TEMPLATES: RecipeTemplate[] = [
  {
    id: 'dessert',
    name: 'Dessert',
    // ... template data
  },
  {
    id: 'main-course',
    name: 'Main Course',
    // ... template data
  },
  // ... 8-10 templates total
];

export function getTemplateById(id: string): RecipeTemplate | null {
  return RECIPE_TEMPLATES.find(t => t.id === id) || null;
}

export function getAllTemplates(): RecipeTemplate[] {
  return RECIPE_TEMPLATES;
}
```

**Template Loading in Service**
```typescript
@Injectable()
export class RecipeTemplatesService {
  async getTemplates(): Promise<RecipeTemplateDto[]> {
    const templates = getAllTemplates();

    // Resolve tag slugs to IDs
    for (const template of templates) {
      const tagIds = await this.resolveTagSlugs(template.defaultTagSlugs);
      template.defaultTagIds = tagIds;
    }

    return templates;
  }

  private async resolveTagSlugs(slugs: string[]): Promise<string[]> {
    const tags = await this.tagsRepository.findBySlug(slugs);
    return tags.map(t => t.id);
  }
}
```

### Creating Recipe from Template

**Template Application Logic** [Source: AC 4, 5]
```typescript
async createFromTemplate(userId: string, dto: CreateFromTemplateDto): Promise<Recipe> {
  // 1. Load template
  const template = getTemplateById(dto.templateId);
  if (!template) {
    throw new BadRequestException('Invalid template ID');
  }

  // 2. Resolve tag slugs to IDs
  const tagIds = await this.resolveTagSlugs(template.defaultTagSlugs);

  // 3. Build CreateRecipeDto with template defaults + user customizations
  const createDto: CreateRecipeDto = {
    title: dto.title || `New ${template.name}`, // User can override
    description: null,
    prepTime: template.defaultFields.prepTime || 0,
    cookTime: template.defaultFields.cookTime || 0,
    servings: dto.servings || template.defaultFields.servings, // User can override
    ingredients: template.placeholderIngredients.map((ing, index) => ({
      ...ing,
      sortOrder: index + 1,
    })),
    steps: template.placeholderSteps,
    tagIds,
  };

  // 4. Create recipe using existing create logic (Story 2.3)
  return await this.recipesService.create(userId, createDto);
}
```

### Tag Resolution Strategy

**Slug to ID Mapping** [Source: AC 3]
- Templates use tag slugs: ["dessert", "sweet"]
- On template load, resolve to Tag IDs from database
- Cache mapping in memory for performance

**Caching Tag Mapping** [Source: Performance optimization]
```typescript
private tagSlugCache: Map<string, string> = new Map(); // slug -> ID

async resolveTagSlugs(slugs: string[]): Promise<string[]> {
  const ids: string[] = [];

  for (const slug of slugs) {
    // Check cache first
    if (this.tagSlugCache.has(slug)) {
      ids.push(this.tagSlugCache.get(slug));
      continue;
    }

    // Query database
    const tag = await this.tagsRepository.findBySlug(slug);
    if (tag) {
      this.tagSlugCache.set(slug, tag.id);
      ids.push(tag.id);
    } else {
      this.logger.warn({ slug, event: 'template_tag_not_found' });
    }
  }

  return ids;
}
```

**Cache Invalidation**
- Cache cleared on app restart (in-memory only)
- V2: Use Redis for persistent cache

### Refactoring Performed

#### File: [apps/api/src/modules/recipes/recipe-templates.service.ts:101-131](apps/api/src/modules/recipes/recipe-templates.service.ts#L101-L131)
- **Change**: Refactored `resolveTagSlugs()` method to eliminate N+1 query anti-pattern
- **Why**: Original implementation queried database inside loop (lines 108-117), causing potential N database queries per template load
- **How**: Moved all uncached slug identification outside loop, performs single batch query for all missing slugs, significantly improving performance when cache is cold

**Before (Inefficient):**
```typescript
for (const slug of slugs) {
  if (cache.has(slug)) { ids.push(cache.get(slug)); continue; }
  // BUG: This queries DB on EVERY iteration
  const uncachedSlugs = slugs.filter(s => !cache.has(s));
  if (uncachedSlugs.length > 0) {
    const tags = await repo.findBySlug(uncachedSlugs); // N queries!
  }
}
```

**After (Optimized):**
```typescript
const uncachedSlugs = slugs.filter(s => !cache.has(s));
if (uncachedSlugs.length > 0) {
  const tags = await repo.findBySlug(uncachedSlugs); // 1 query!
  // Populate cache
}
for (const slug of slugs) { /* Build result from cache */ }
```

**Performance Impact**: Reduces database queries from O(N) to O(1) for template loading, critical for GET /recipe-templates endpoint performance.

#### File: [apps/api/src/modules/recipes/recipe-templates.service.ts:70](apps/api/src/modules/recipes/recipe-templates.service.ts#L70)
