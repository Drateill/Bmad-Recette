# Story 1.9: Mobile App Foundation & Authentication UI

## Status
Ready for Review - All blocking QA issues resolved, P0 tests implemented

## Story
**As a** mobile user,
**I want** a functional mobile app with login/register screens,
**so that** I can create an account and log in from my iOS or Android device.

## Acceptance Criteria
1. React Native with Expo scaffolded in /packages/mobile with TypeScript
2. React Navigation configured with authentication flow (Auth stack vs. App stack)
3. Login screen created with email and password inputs, "Sign in" button, and OAuth buttons
4. Registration screen created with email, password, firstName inputs and "Create account" button
5. Form validation implemented using React Hook Form + Zod (matching web validation)
6. Authentication state managed using Zustand (shared store from /packages/shared)
7. JWT tokens stored in AsyncStorage with secure encryption (expo-secure-store)
8. OAuth flow implemented using expo-auth-session for Google and Apple
9. Loading states, error messages, and keyboard-aware scroll views implemented for good UX

### Authentication State Management
**Zustand Store (Shared between Web and Mobile):**
```typescript
// packages/shared/src/stores/authStore.ts
interface AuthState {
  user: User | null;
  accessToken: string | null;
  refreshToken: string | null; // Mobile stores refresh token (not cookie)
  isAuthenticated: boolean;
  isLoading: boolean;
  error: string | null;

  login: (email: string, password: string) => Promise<void>;
  register: (email: string, password: string, firstName: string) => Promise<void>;
  logout: () => Promise<void>;
  refreshAccessToken: () => Promise<void>;
  setTokens: (accessToken: string, refreshToken: string) => void;
  clearAuth: () => void;
}
```

**Mobile-Specific Token Storage:**
- **Access Token:** Stored in SecureStore (encrypted)
- **Refresh Token:** Stored in SecureStore (encrypted)
- **Rationale:** Mobile apps need persistence (app restarts), cookies don't work in native apps

**Web vs Mobile Token Storage:**
| Aspect | Web | Mobile |
|--------|-----|--------|
| Access Token | In-memory (not persisted) | SecureStore (encrypted, persisted) |
| Refresh Token | httpOnly cookie (backend sets) | SecureStore (encrypted, persisted) |
| Refresh API | Cookie sent automatically | Refresh token in request body |
| Persistence | No (must log in after browser close) | Yes (stays logged in after app restart) |

### Mobile API Client Configuration
**Key Differences from Web:**
```typescript
// apps/mobile/src/services/apiClient.ts
const apiClient = axios.create({
  baseURL: Constants.expoConfig?.extra?.apiBaseUrl || 'http://localhost:3001',
  withCredentials: false, // Mobile doesn't use cookies
  headers: {
    'Content-Type': 'application/json',
  },
});

// Request interceptor: Add auth token from SecureStore
apiClient.interceptors.request.use(async (config) => {
  const token = await SecureStore.getItemAsync('accessToken');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// Response interceptor: Handle 401 and refresh token
apiClient.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;

    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;

      try {
        const refreshToken = await SecureStore.getItemAsync('refreshToken');
        const { accessToken } = await authService.refreshAccessToken(refreshToken);
        await SecureStore.setItemAsync('accessToken', accessToken);
        originalRequest.headers.Authorization = `Bearer ${accessToken}`;
        return apiClient(originalRequest);
      } catch (refreshError) {
        await SecureStore.deleteItemAsync('accessToken');
        await SecureStore.deleteItemAsync('refreshToken');
        // Navigation to Auth Stack handled by authStore state change
        return Promise.reject(refreshError);
      }
    }

    return Promise.reject(error);
  }
);
```

### Navigation Architecture
**Auth Flow Pattern:**
```typescript
// apps/mobile/src/navigation/AppNavigator.tsx
import { NavigationContainer } from '@react-navigation/native';
import { createStackNavigator } from '@react-navigation/stack';
import { useAuthStore } from '@bmad/shared/stores/authStore';

const AuthStack = createStackNavigator();
const AppStack = createStackNavigator();

function AuthNavigator() {
  return (
    <AuthStack.Navigator screenOptions={{ headerShown: false }}>
      <AuthStack.Screen name="Login" component={LoginScreen} />
      <AuthStack.Screen name="Register" component={RegisterScreen} />
    </AuthStack.Navigator>
  );
}

function AppNavigator() {
  return (
    <AppStack.Navigator>
      <AppStack.Screen name="Recipes" component={RecipesScreen} />
    </AppStack.Navigator>
  );
}

export function RootNavigator() {
  const isAuthenticated = useAuthStore((state) => state.isAuthenticated);

  return (
    <NavigationContainer>
      {isAuthenticated ? <AppNavigator /> : <AuthNavigator />}
    </NavigationContainer>
  );
}
```

**Navigation Automatic on Auth State Change:**
- When user logs in: `isAuthenticated` becomes true → App Stack shown
- When user logs out: `isAuthenticated` becomes false → Auth Stack shown
- No manual navigation needed (React re-renders based on state)

### OAuth Implementation with expo-auth-session
**Mobile OAuth Flow Differences from Web:**
1. **Deep Linking:** OAuth callback uses app scheme (e.g., `exp://192.168.1.5:19000/--/`)
2. **Browser Flow:** Opens system browser (not embedded WebView for security)
3. **Token Exchange:** Mobile exchanges OAuth code for tokens via backend API
4. **No Cookie:** Backend returns refresh token in response body (not cookie)

**Implementation:**
```typescript
// apps/mobile/src/services/oauthService.ts
import * as AuthSession from 'expo-auth-session';
import * as WebBrowser from 'expo-web-browser';

// Required for iOS
WebBrowser.maybeCompleteAuthSession();

export async function loginWithGoogle() {
  const discovery = {
    authorizationEndpoint: 'https://accounts.google.com/o/oauth2/v2/auth',
    tokenEndpoint: 'https://oauth2.googleapis.com/token',
  };

  const redirectUri = AuthSession.makeRedirectUri({
    useProxy: true, // Use Expo proxy for development
  });

  const [request, response, promptAsync] = AuthSession.useAuthRequest(
    {
      clientId: Constants.expoConfig?.extra?.googleClientId,
      scopes: ['openid', 'profile', 'email'],
      redirectUri,
    },
    discovery
  );

  const result = await promptAsync();

  if (result.type === 'success') {
    const { code } = result.params;
    // Exchange code for tokens via backend
    const { user, accessToken, refreshToken } = await authService.exchangeOAuthCode('google', code);
    return { user, accessToken, refreshToken };
  }

  throw new Error('OAuth authentication failed');
}
```

```typescript
// apps/mobile/src/screens/LoginScreen.tsx (simplified)
import { useForm, Controller } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { TextInput, Button } from 'react-native-paper';
import { loginSchema } from '@bmad/shared/schemas/authSchemas';

export function LoginScreen() {
  const { control, handleSubmit, formState: { errors } } = useForm({
    resolver: zodResolver(loginSchema),
  });

  const onSubmit = async (data) => {
    await authStore.login(data.email, data.password);
  };

  return (
    <ScrollView keyboardShouldPersistTaps="handled">
      <KeyboardAvoidingView behavior="padding">
        <Controller
          control={control}
          name="email"
          render={({ field }) => (
            <TextInput
              label="Email"
              value={field.value}
              onChangeText={field.onChange}
              error={!!errors.email}
              keyboardType="email-address"
              autoCapitalize="none"
            />
          )}
        />
        {errors.email && <HelperText type="error">{errors.email.message}</HelperText>}

        <Controller
          control={control}
          name="password"
          render={({ field }) => (
            <TextInput
              label="Password"
              value={field.value}
              onChangeText={field.onChange}
              secureTextEntry
              error={!!errors.password}
            />
          )}
        />
        {errors.password && <HelperText type="error">{errors.password.message}</HelperText>}

        <Button mode="contained" onPress={handleSubmit(onSubmit)} loading={isLoading}>
          Sign in
        </Button>
      </KeyboardAvoidingView>
    </ScrollView>
  );
}
```

### Security Considerations
**Mobile Security:** [Source: [security-and-performance.md](../architecture/security-and-performance.md#authentication-security)]
- **Secure Token Storage:** expo-secure-store uses iOS Keychain and Android Keystore
- **No Plain Text Storage:** Never use AsyncStorage for tokens (unencrypted)

- **Biometric Auth:** Future enhancement (Touch ID, Face ID) for quick re-auth

#### 5. OAuth Flow Implementation Concerns (HIGH)
**Location**: [apps/mobile/src/services/oauthService.ts:48-62](apps/mobile/src/services/oauthService.ts#L48-L62)

**Issue**:
```typescript
const result = await AuthSession.exchangeCodeAsync(...);

```

**Problem**:
- `exchangeCodeAsync` returns an access token from Google
- This access token is then sent to backend as a "code"
- Backend endpoint expects authorization code, not access token

**Standard OAuth Flow Should Be**:
1. `promptAsync()` → Get authorization code
2. Send authorization code to backend
3. Backend exchanges code for tokens with provider
4. Backend returns app tokens

**Current Implementation Appears To**:
1. Exchange code for provider access token
2. Send provider access token to backend (labeled as "code")
3. Backend unclear how it handles this

**Recommendation**: Review OAuth flow architecture with backend team. Either:
- Send authorization code directly to backend (recommended)
- Or document if backend expects provider access token
