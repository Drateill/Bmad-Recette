## Dev Notes

### Architecture Context

**Technology Stack** [Source: architecture/tech-stack.md]
- **Database**: PostgreSQL 15+
- **ORM**: Prisma 5.8+ (superior DX over TypeORM, type-safe queries, excellent migration tooling)
- **Backend Framework**: NestJS 10.3+ with modular architecture
- **Language**: TypeScript 5.3+ in strict mode

**Data Model Design Decisions** [Source: architecture/data-models.md#data-model-design-decisions]
1. **UUIDs over Auto-increment IDs**: Enables offline creation without ID conflicts during sync
2. **Denormalized ingredientName in RecipeIngredient**: Handles custom ingredients not in global catalog without breaking foreign keys
3. **Version field on Recipe**: Enables optimistic locking for conflict detection during sync
4. **Arrays in PostgreSQL** (commonUnits): Leverages PostgreSQL's native array support for simple storage
5. **Separate Photo entity**: Allows multiple photos per recipe with granular metadata (primary photo, thumbnails)

### Database Schema Details

**Recipe Model** [Source: architecture/database-schema.md, architecture/data-models.md#recipe]
```prisma
model Recipe {
  id          String   @id @default(uuid())
  userId      String
  title       String
  description String?
  prepTime    Int
  cookTime    Int
  servings    Int
  rating      Int?
  source      String?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  version     Int      @default(1)

  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  ingredients RecipeIngredient[]
  steps       RecipeStep[]
  photos      RecipePhoto[]
  tags        RecipeTag[]

  @@index([userId])
  @@index([title])
  @@map("recipes")
}
```

**Ingredient Model** [Source: architecture/database-schema.md, architecture/data-models.md#ingredient]
```prisma
model Ingredient {
  id           String   @id @default(uuid())
  name         String   @unique
  category     String
  commonUnits  String[]
  averagePrice Float?
  priceUnit    String?
  createdAt    DateTime @default(now())

  recipeIngredients RecipeIngredient[]
  inventoryItems    InventoryItem[]

  @@index([name])
  @@map("ingredients")
}
```

**Ingredient Categories**: Produce, Meat/Seafood, Dairy, Bakery, Canned Goods, Frozen, Spices, Pantry, Other [Source: architecture/data-models.md#ingredient]

**RecipeIngredient Junction Model** [Source: architecture/database-schema.md, architecture/data-models.md#recipeingredient]
- **Key Design**: `ingredientId` is nullable to support custom ingredients not in global catalog
- **Denormalized**: `ingredientName` always present for display (even if ingredientId is null)
- **sortOrder**: Enables user-defined ordering of ingredients in recipe display

**RecipeStep Model** [Source: architecture/data-models.md#recipestep]
- **stepNumber**: Sequential order (1, 2, 3...) - must be enforced at application level
- **duration**: Optional time for this specific step in minutes (for advanced recipes)

**RecipePhoto Model** [Source: architecture/data-models.md#recipephoto]
- **isPrimary**: Only one photo per recipe should have isPrimary=true (application logic)
- **s3Url**: Full S3 URL to original image (stored in AWS S3, not database)
- **thumbnailUrl**: S3 URL to 400x400 thumbnail (generated by Sharp library in future story)

### Coding Standards

**Critical Rules** [Source: architecture/coding-standards.md#critical-fullstack-rules]
- **Type Sharing**: Always define types in `packages/shared/types` and import from `@bmad/shared/types`
- **Database Access**: All queries through Repository pattern (not direct Prisma in this story, but schema foundation)
- **Naming Conventions**: Database tables use snake_case (e.g., `recipe_ingredients`, `recipe_steps`)

**Database Table Naming** [Source: architecture/coding-standards.md#naming-conventions]
- Use `@@map("table_name")` in Prisma to enforce snake_case table names
- Example: `@@map("recipe_ingredients")` for RecipeIngredient model

### Foreign Key and Cascade Rules

**Cascade Deletion Strategy** [Source: architecture/database-schema.md]
- User deletion → CASCADE deletes all recipes (onDelete: Cascade)
- Recipe deletion → CASCADE deletes all ingredients, steps, photos (onDelete: Cascade)
- Ingredient deletion → NULLABLE (set null) for RecipeIngredient.ingredientId (custom ingredients)

**Indexes for Performance** [Source: architecture/data-models.md, PRD NFR requirements]
- Recipe: Index on `userId` (user's recipe list queries), Index on `title` (search functionality)
- Ingredient: Index on `name` (autocomplete queries)
- RecipeIngredient: Index on `recipeId` and `ingredientId` (join queries)
- RecipeStep: Index on `recipeId` (fetching recipe steps)
- RecipePhoto: Index on `recipeId` (fetching recipe photos)

### Migration Best Practices

**Migration Creation** [Source: Prisma best practices, AC: 7]
1. Always name migrations descriptively: `create-recipe-schema`, not `init`
2. Review generated SQL before applying to production
3. Test rollback capability: `npx prisma migrate reset` then re-apply
4. Never edit migration files manually after generation
5. Commit migration files to git (required for team collaboration)

**Rollback Strategy**
- Development: `npx prisma migrate reset` (drops database and re-applies all migrations)
- Production: Manual rollback by applying reverse migration SQL (future consideration)
