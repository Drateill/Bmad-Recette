# Story 1.7: JWT Token Refresh & Session Management

## Status
Done

## Story
**As a** logged-in user,
**I want** my session to be automatically renewed when my access token expires,
**so that** I don't have to log in repeatedly during active use.

## Acceptance Criteria
1. POST /api/auth/refresh endpoint created accepting refresh token from httpOnly cookie
2. Refresh token validated (signature, expiration) and checked against Redis session store
3. Valid refresh returns new access token (15 min expiry) and optionally rotates refresh token
4. Expired or invalid refresh token returns 401 Unauthorized, requiring new login
5. POST /api/auth/logout endpoint created, invalidating refresh token in Redis and clearing cookie
6. Redis stores refresh tokens with TTL matching expiration (7 days), auto-cleanup on expiry
7. Concurrent refresh requests handled gracefully (idempotent within 5-second window)

### JWT Configuration
**Access Token:** [Source: [security-and-performance.md](../architecture/security-and-performance.md#authentication-security)]

- Stored: Frontend memory (not localStorage/sessionStorage for security)
- Algorithm: HS256 (HMAC SHA-256)
- Secret: `JWT_SECRET` environment variable

**Refresh Token:** [Source: [security-and-performance.md](../architecture/security-and-performance.md#authentication-security)]
- Expiry: 7 days (604800 seconds)
- Stored: httpOnly cookie (XSS-proof)
- Algorithm: HS256 (HMAC SHA-256)
- Secret: `JWT_REFRESH_SECRET` environment variable (separate from access token secret)
- Cookie options: `{ httpOnly: true, secure: true, sameSite: 'strict', path: '/api/auth', maxAge: 604800000 }`

### Redis Session Store
**Technology:** Redis 7+ [Source: [tech-stack.md](../architecture/tech-stack.md#technology-stack-table)]
- **Purpose:** Session store and sync coordination
- **Connection:** Already configured in Story 1.2 (Backend API Foundation)
- **Redis Key Pattern for Refresh Tokens:** `refresh_token:${userId}:${tokenId}`
  - userId: UUID of the user
  - tokenId: jti (JWT ID) claim from refresh token payload
- **Redis Value:** JSON string: `{ userId, tokenId, createdAt, expiresAt }`
- **TTL:** 7 days (604800 seconds) - matches refresh token expiration
- **Auto-Cleanup:** Redis automatically deletes expired keys via TTL

**Redis Operations:**
- **Store:** `redis.setex(key, ttl, value)` - Set key with expiration
- **Retrieve:** `redis.get(key)` - Get key value
- **Delete:** `redis.del(key)` - Delete key
- **Connection:** Injected via `RedisService` or `@Inject('REDIS_CLIENT')`

[Source: [tech-stack.md](../architecture/tech-stack.md#technology-stack-table)]

### Token Refresh Flow
**Standard Refresh Flow:**
```
1. User's access token expires (15 min)
   ↓
2. Frontend detects 401 response from protected endpoint
   ↓
3. Frontend calls POST /api/auth/refresh (refresh token in httpOnly cookie)
   ↓
4. Backend extracts refresh token from cookie
   ↓
5. Backend verifies JWT signature and expiration
   ↓
6. Backend checks if refresh token exists in Redis (key: refresh_token:userId:tokenId)
   ↓
7. If valid, backend generates new access token (15 min expiry)
   ↓
8. Optionally, backend generates new refresh token (rotation)
   ↓
9. Backend returns new access token in response body
   ↓
10. Frontend stores new access token in memory and retries original request
```

**Refresh Token Rotation (Optional for MVP, but Recommended):**
- Generate new refresh token on each refresh
- Invalidate old refresh token immediately
- Store new refresh token in Redis with 7-day TTL
- Keep old token valid for 5 seconds (idempotency window)
- Prevents token replay attacks

[Source: [api-specification.md](../architecture/api-specification.md#rest-api-specification)]

### Logout Flow
**Logout Flow:**
```
1. User clicks "Logout" button
   ↓
2. Frontend calls POST /api/auth/logout (refresh token in httpOnly cookie)
   ↓
3. Backend extracts refresh token from cookie
   ↓
4. Backend decodes token to get userId and tokenId (don't verify, just decode)
   ↓
5. Backend deletes refresh token from Redis: redis.del('refresh_token:userId:tokenId')
   ↓
6. Backend clears refresh token cookie: res.clearCookie('refreshToken')
   ↓
7. Backend returns 204 No Content
   ↓
8. Frontend clears access token from memory
   ↓
9. Frontend redirects to /login page
```

**Graceful Logout:**
- If refresh token missing, still clear cookie and return 204
- If Redis connection fails, log error but still return 204 (don't block logout)
- Don't throw exceptions on logout - always succeed from user perspective

[Source: [api-specification.md](../architecture/api-specification.md#rest-api-specification)]

### Concurrent Refresh Handling
**Problem:** User has multiple browser tabs, both try to refresh simultaneously
**Solution:** Idempotency window (5 seconds)

**Implementation:**
1. When rotating refresh token, keep old token in Redis for 5 seconds
2. New key: `refresh_token_old:${userId}:${oldTokenId}` with 5-second TTL
3. Value: JSON with new access token (cached)
4. If old token used within 5 seconds, return cached new access token
5. After 5 seconds, old token expires and becomes invalid

**Edge Cases:**
- Multiple tabs refresh within 5 seconds → all get same new access token (idempotent)
- Multiple tabs refresh after 5 seconds → only first succeeds, others get 401 (must refresh again)
- This prevents token desync across tabs while maintaining security

[Source: AC 7]

### Error Handling
**Refresh Token Errors:**

1. **Missing Refresh Token**
   - Trigger: No `refreshToken` cookie in request
   - Response: 401 Unauthorized
   - Message: "Refresh token not provided"
   - Action: Frontend redirects to /login

2. **Invalid JWT Signature**
   - Trigger: Refresh token signature doesn't match secret
   - Response: 401 Unauthorized
   - Message: "Invalid refresh token"
   - Log security event (potential attack)

3. **Expired Refresh Token**
   - Trigger: Token exp claim < current time
   - Response: 401 Unauthorized
   - Message: "Refresh token expired"
   - Action: Frontend redirects to /login

4. **Token Not in Redis**
   - Trigger: Refresh token valid JWT, but not found in Redis
   - Response: 401 Unauthorized
   - Message: "Invalid refresh token"
   - Common cause: User logged out on another device

5. **Redis Connection Failure**
   - Trigger: Redis unavailable during refresh check
   - Response: 503 Service Unavailable
   - Message: "Session service temporarily unavailable"
   - Action: Frontend retries after delay

**Logout Errors:**
- Graceful handling: Always return 204 even if token missing or Redis fails
- Log errors for monitoring but don't block user logout

[Source: [error-handling-strategy.md](../architecture/error-handling-strategy.md#error-response-format)]

### Security Considerations
**Refresh Token Security:**
- **httpOnly cookie:** Prevents XSS attacks (JavaScript cannot access token)
- **Secure flag:** HTTPS-only transmission (prevents MITM in production)
- **SameSite=Strict:** Prevents CSRF attacks
- **Path=/api/auth:** Limits cookie scope to auth endpoints only
- **Separate secret:** JWT_REFRESH_SECRET different from JWT_SECRET
- **Redis storage:** Enables token revocation (logout invalidates token)
- **Token rotation:** Reduces window of vulnerability if token compromised
- **Idempotency window:** Prevents token desync without sacrificing security

**Rate Limiting:**
- Refresh endpoint: 10 requests/minute per IP (same as login)
- Prevents brute-force token attacks

**Logging:**
- Log all refresh failures for security monitoring
- Log token ID (jti) for audit trail, NOT full token

**Store Refresh Token in Redis:**
```typescript
async storeRefreshToken(userId: string, tokenId: string, expiresAt: Date): Promise<void> {
  const key = this.getRefreshTokenKey(userId, tokenId);
  const value = JSON.stringify({ userId, tokenId, createdAt: new Date(), expiresAt });
  const ttl = 7 * 24 * 60 * 60; // 7 days in seconds
  await this.redisClient.setex(key, ttl, value);
}
```

**Refresh Access Token:**
```typescript
async refreshAccessToken(refreshToken: string): Promise<{ accessToken: string }> {
  // Verify JWT signature and expiration
  let payload;
  try {
    payload = this.jwtService.verify(refreshToken, { secret: this.configService.get('JWT_REFRESH_SECRET') });
  } catch (error) {
    throw new UnauthorizedException('Invalid refresh token');
  }

  const { userId, jti: tokenId } = payload;

  // Check if token exists in Redis
  const key = this.getRefreshTokenKey(userId, tokenId);
  const storedToken = await this.redisClient.get(key);

  if (!storedToken) {
    throw new UnauthorizedException('Invalid refresh token');
  }

  // Generate new access token
  const accessToken = this.generateAccessToken(userId, payload.email);

  // Optional: Rotate refresh token (generate new one, invalidate old)
  // const newRefreshToken = this.generateRefreshToken(userId, payload.email);
  // await this.storeRefreshToken(userId, newRefreshTokenId, ...);
  // await this.redisClient.del(key); // Invalidate old token
  // Keep old token for 5 seconds (idempotency)
  // await this.redisClient.setex(this.getOldRefreshTokenKey(userId, tokenId), 5, accessToken);

  return { accessToken };
}
```

**Logout:**
```typescript
async logout(refreshToken: string): Promise<void> {
  try {
    // Decode token (don't verify, just extract userId and tokenId)
    const payload = this.jwtService.decode(refreshToken) as { userId: string; jti: string };
    if (payload && payload.userId && payload.jti) {
      const key = this.getRefreshTokenKey(payload.userId, payload.jti);
      await this.redisClient.del(key);
      this.logger.log(`User ${payload.userId} logged out, token ${payload.jti} invalidated`);
    }
  } catch (error) {
    // Log error but don't throw - logout should always succeed from user perspective
    this.logger.error('Logout error', error);
  }
}
```
