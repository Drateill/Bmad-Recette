# Story 8.2: UI Revamp - Core Flow Screens

## Status
Approved

## Story
**As a** user,
**I want** the core recipe, discovery, menu, and shopping flows to follow the new UI spec,
**so that** I can complete key tasks faster with less friction.

## Acceptance Criteria

1. Recipe Library (grid/list), Recipe Detail (tabbed layout), and Create/Edit recipe surfaces match the spec's layouts, components, and interaction notes
2. Discover by Ingredients flow matches the spec, including match groupings and missing-item cues
3. Menu Planner calendar view aligns with the spec, including empty-slot actions and generation controls
4. Shopping Lists list view and active list detail view match the spec, including organization modes and progress tracking
5. Empty, loading, and error states are implemented per spec for each updated screen
6. Existing routes, APIs, and analytics events remain unchanged
7. Scope is web UI (`apps/web`) only; mobile UI changes are out of scope for this story

## Tasks / Subtasks

- [ ] Task 1: Revamp Recipe Library and Recipe Detail UI (AC: 1, 5, 6)
  - [ ] Apply Recipe Grid View layout and card design
  - [ ] Implement recipe detail tabbed layout with action bar
  - [ ] Update create/edit recipe surfaces to align with spec layout patterns

- [ ] Task 2: Revamp Discover by Ingredients UI (AC: 2, 5, 6)
  - [ ] Implement ingredient bar with removable chips
  - [ ] Add match grouping and missing-item cues

- [ ] Task 3: Revamp Menu Planner UI (AC: 3, 5, 6)
  - [ ] Implement calendar grid layout and empty slot actions
  - [ ] Align generation controls and menu info card

- [ ] Task 4: Revamp Shopping List UI (AC: 4, 5, 6)
  - [ ] Update list management view with active/past list sections
  - [ ] Update active list detail view with organization toggle and progress

- [ ] Task 5: State handling and UI feedback (AC: 5)
  - [ ] Implement loading skeletons/shimmers where specified
  - [ ] Implement empty states and error feedback

- [ ] Task 6: Align screen updates to existing routes (AC: 6, 7)
  - [ ] Recipes routes remain `/recipes`, `/recipes/:id`, `/recipes/new`
  - [ ] If new routes are introduced for Discover/Menu/Shopping, document them and keep existing APIs unchanged
